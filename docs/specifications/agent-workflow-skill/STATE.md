## Binding decisions
- The skill is a separate `host.Host.Skills() []File` list, never an entry in `Plugin()`. `File.RelPath` is install-root-relative; the skill's own entry is `host.WorkflowSkillDir + "/SKILL.md"`. Setup report kind `setup.KindSkill = "skill"`; artifact kind `artifact.KindSkillWorkflow`. Init row order: config, feature-root, plugin…, hook, skill, agent…, bound-agent…, snippet. Uninstall row order is the strict reverse: snippet, bound-agent…, agent…, skill, plugin…, config. brief owns `host.PluginDir` and below **and** `host.WorkflowSkillDir`; prune stops at each. (SCENARIO-01, S07, S08)
- Older-render upgrade is generic in `setup` (`OriginOlder` → `ActionMerged`/"updated", `verifyFileUnchanged`-guarded, removed like current on Uninstall without `--force`). `renderAgent` takes optional `skills []string`; reviewer never gets `skills:` (R15). (SCENARIO-02)
- Binding classification lives in `internal/platform/agentfile`: `ResolveBinding`, `(Binding).LackingSkill`, `Find` (frontmatter `name:`, project shadows user, no filename fallback), `Parse` (bytes-level twin of `Load`, shares `decode`). Doctor and setup may import only `internal/platform/*`. (SCENARIO-03/06/07)
- `--edit-agents` and Uninstall's own removal **share one target selector**, `boundAgentTargets(root, home, roles)` (`internal/setup/bound_agent.go`): every bare-name planner/implementer binding's own `ScopeProject` `agentfile.Definition`, deduped by path, planner-then-implementer order. `addWorkflowSkill`/`removeWorkflowSkill` are exact inverses over one frontmatter `skills:` key — insert/block-list/flow-list shapes only; every other shape (`shapeOther`, or a quoted/commented/multi-line value) is untouched, `ActionKept` on add, **no row at all** on removal. Neither is trusted on its own: `planBoundAgent`/`planBoundAgentRemoval` re-decode the edited bytes (`agentfile.Parse`) and require `boundAgentEditVerified`/`boundAgentRemovalVerified` — Name unchanged, Skills exactly original±the skill — before applying; a mismatch (a folded block continuation, a quoted flow item split on an internal comma, a duplicate entry, `skills :`/`"skills":` producing a second key) falls back to the unedited `ActionKept`/no-row path rather than writing a shape the text scanner misjudged. Emptying a block or flow list to zero items **drops the `skills:` key line**, never `skills: []`, including via a trailing comma (`[a,]`, `[brief-workflow,]`). A non-regular leaf (checked via `os.Lstat`, never `os.Stat` — a dangling symlink must stay a kept/no-row leaf, not a hard error) or an escaping resolved path (`.claude` symlinked outside root) gets no row either way. `writeBoundAgent` preserves the leaf's own Lstat'd mode and writes through an `os.Root` opened at planning time's own `resolvedRoot`, confined the same way the escape check already was, rather than re-resolving the leaf's raw path at apply time. (SCENARIO-07, SCENARIO-08, fix pass 1)
- Uninstall's bound-agent rows (`planBoundAgentRemovals`) are planned only when the brief-workflow skill's own row is **not** `ActionKept` (Rule 8's gate: edited without `--force`, or non-regular even with `--force`, keeps every entry). Roles come from `config.Inspect(nearest)`; `nearest == ""` or any read/decode error means no bound rows, never a refusal — Uninstall's config handling stays digest-only throughout. A bound-agent row is `ActionRemoved` but the file is **rewritten in place**, never deleted: its path lands in `Result.Modified`, never `Result.Removed`; `applyUninstall`'s `os.Remove` loop explicitly skips `KindBoundAgent`. Row order among bound-agent rows is implementer-before-planner (strict reversal of `--edit-agents`' own planner-first walk). No new flag; stdout row `removed <rel> (brief-workflow from skills)`; `uninstallLong` and `--json`'s `modified`/`removed` split updated accordingly. (SCENARIO-08)

## Traps
- `filepath.WalkDir` does not walk a symlinked directory as its own root — only a symlinked leaf `.md` file is read through its link. A test needing "resolves via `Find`ID but escapes root" must symlink an ancestor of `agents`, not `agents` itself.
- R10's writability pre-check (`checkWritable`) Lstats a symlinked `.claude` directly and always reports "not a directory" — Init-side tests exercising a symlinked `.claude` for another reason must use `DryRun` or pre-materialize the file. **Uninstall has no writability pre-check at all** (by design — see Open debts).
- Every bare-name-role test must inject home (`WithHomeDir` / `withSetupOpts`) — `cli.Run`'s exported tests cannot; use the `run()` seam (`init_internal_test.go`'s / `uninstall_internal_test.go`'s pattern). A home directory under a *sibling* `t.TempDir()` sits outside root, so the escape check alone excludes it — a test isolating the `ScopeProject` filter specifically must nest home *inside* root.
- `agentfile` imports `internal/platform/host`; neither `host` nor `artifact` may import `agentfile` (cycle).
- `apply`/`writableTargets`/`printArtifacts` (Init) and `applyUninstall` (Uninstall) all take a `boundAgentArts` parameter — every call site, including white-box tests in `apply_internal_test.go`, must pass one (`nil` where irrelevant).
- R16's byte identity on the `--edit-agents` → Uninstall round trip holds only for "no key", a non-empty block list, and canonical `skills: [a]`. An original `skills: []` loses its line entirely (ruled), and `skills:[a]`/`skills:  [a]` normalizes to `skills: [a]` — do not "fix" either without a ruling.
- `Test_uninstall_treats_an_unparseable_or_invalid_config_as_edited` must stay green — a decode failure in Uninstall's own `config.Inspect` call (bound-agent path) must never surface as a refusal.
- A dangling symlink at a bound-agent path never reaches `planBoundAgent`/`planBoundAgentRemoval` through Init's or Uninstall's own real flow — `agentfile.Find` reads a candidate's bytes to decode `name:` before it is ever a target, and `os.ReadFile` on a dangling symlink always errors, filtering it out of `boundAgentTargets` before either function runs. Testing that guard means calling `planBoundAgent`/`planBoundAgentRemoval` directly (white-box, `bound_agent_internal_test.go`), not through `srv.Init`/`srv.Uninstall`. (fix pass 1)

## Traps
- `filepath.WalkDir` does not walk a symlinked directory as its own root — only a symlinked leaf `.md` file is read through its link. A test needing "resolves via `Find` but escapes root" must symlink an ancestor of `agents`, not `agents` itself.
- R10's writability pre-check (`checkWritable`) Lstats a symlinked `.claude` directly and always reports "not a directory" — Init-side tests exercising a symlinked `.claude` for another reason must use `DryRun` or pre-materialize the file. **Uninstall has no writability pre-check at all** (by design — see Binding decisions).
- Every bare-name-role test must inject home (`WithHomeDir` / `withSetupOpts`) — `cli.Run`'s exported tests cannot; use the `run()` seam. A home directory under a *sibling* `t.TempDir()` sits outside root, so the escape check alone excludes it — a test isolating the `ScopeProject` filter specifically must nest home *inside* root.
- `agentfile` imports `internal/platform/host`; neither `host` nor `artifact` may import `agentfile` (cycle).
- `apply`/`writableTargets`/`printArtifacts` (Init) and `applyUninstall` (Uninstall) all take a `boundAgentArts` parameter — every call site, including white-box tests, must pass one (`nil` where irrelevant).
- R16's byte identity on the `--edit-agents` → Uninstall round trip holds only for "no key", a non-empty block list, and canonical `skills: [a]`. An original `skills: []` loses its line entirely (ruled), and `skills:[a]`/`skills:  [a]` normalizes to `skills: [a]` — do not "fix" either without a ruling.
- A dangling symlink at a bound-agent path never reaches `planBoundAgent`/`planBoundAgentRemoval` through Init's or Uninstall's own real flow — `agentfile.Find` filters it out of `boundAgentTargets` first. Testing that guard means calling `planBoundAgent`/`planBoundAgentRemoval` directly (white-box), not through `srv.Init`/`srv.Uninstall`.
